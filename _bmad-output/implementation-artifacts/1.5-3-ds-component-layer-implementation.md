## Story

As a 前端开发团队,
I want 所有在 `_bmad-output/D-Design-System/components/*.md` 中定义但尚未落地的 DS 组件在 `packages/ui/src/` 实现并有 Storybook 覆盖,
so that Epic 1.5-5 / 1.5-6 / 1.5-7 以及后续 Epic 的 UI 工作能复用一致组件层，不再在页面里现场近似实现。

## Acceptance Criteria

1. **Given** `_bmad-output/planning-artifacts/ds-component-implementation-checklist.md` 标记 `packages/ui/src/` 当前已实现 `button / text-input / text / provider`，且 16 个组件待实现  
   **When** 本 Story 完成  
   **Then** `packages/ui/src/` 新增并导出以下 16 个组件：`avatar`、`badge`、`bottom-tab-bar`、`card`、`chart`、`divider`、`filter-chip`、`header`、`modal-sheet`、`progress`、`search-bar`、`skeleton`、`tab`、`toast`、`toggle`、`tooltip`。
2. 每个新增组件的 Props、状态、变体、accessibility role/label 必须逐项对齐对应 spec：`_bmad-output/D-Design-System/components/<component>.md`；spec 未覆盖但实现必须决策的行为，必须写入组件注释或 Storybook story 说明，不得静默自创口径。
3. 每个组件必须使用 `packages/ui/tamagui.config.ts` 中已有 Tamagui token、`shadows` 常量或明确登记在 `packages/ui/token-mapping.md` 的映射；禁止硬编码颜色、间距、字号、圆角、阴影近似值。唯一允许的字面量是 spec 明确给出的算法值或平台 API 要求值，并需局部注释说明。
4. 每个组件必须新增对应 Storybook Story，覆盖 Default、主要 variants、disabled/error/loading/empty 等适用状态；Storybook 必须能通过 `pnpm --filter @money-tracker/ui storybook` 启动，且 `pnpm --filter @money-tracker/ui build-storybook` 或等效构建命令无错误。
5. 每个组件必须新增单元测试，位置为 `packages/ui/src/__tests__/<component>.test.tsx` 或与现有测试组织一致的同包测试路径；测试覆盖默认渲染、主要变体、关键交互、禁用态不触发交互、可访问性属性。
6. `packages/ui/src/index.ts` 是唯一对外入口；新增组件及 Props interface/type 必须从该文件具名导出，禁止消费者通过 `@money-tracker/ui/src/*` 子路径导入。
7. `chart` 组件必须遵循最新架构口径：优先使用 Skia / `victory-native` 体系，覆盖 donut / line / radar / bar 四类接口；不得用 SVG 手写替代。Web/Storybook 环境如无法加载原生 Skia，必须提供明确的可访问 fallback，且不得破坏构建。
8. `bottom-tab-bar` 必须与后续 Story 1.5.4 的 Expo Router `Tabs` 外壳兼容，支持 active/inactive、badge 红点/数字、4-tab spec（首页/交易/AI/我的）和本轮 Epic 1.5 实际落地的 3-tab 导航适配（dashboard/report/my-hub）。
9. `modal-sheet` 必须明确 alert / sheet / picker 三种形态，使用 Tamagui `Sheet` / `AlertDialog` / `Dialog` 或 `@gorhom/bottom-sheet` 中一种一致实现；若新增 `@gorhom/bottom-sheet`，必须锁定版本并记录 Reanimated/Gesture 依赖兼容性。
10. `toast` 必须由 `UIProvider` 或包内 provider 承载全局单例能力，支持 success / error / warning / info 队列，不得要求页面各自临时实现 Toast 容器。
11. 更新 `_bmad-output/planning-artifacts/ds-component-implementation-checklist.md`：16 个组件逐项勾选，质量闸门勾选，并在变更日志记录本 Story 完成情况。
12. 验证必须通过：`pnpm --filter @money-tracker/ui lint`、`pnpm --filter @money-tracker/ui test`、`pnpm --filter @money-tracker/ui build`、Storybook 启动/构建命令，以及根目录 `pnpm test`；若 Windows 环境存在非代码阻塞，必须在 Dev Agent Record 记录命令、错误、可复现条件和替代验证证据。

### 当前代码现状

- `packages/ui/tamagui.config.ts` 已定义 brand / neutral / semantic / category / surface token、font scale、component heights、radius、animations 和 `shadows` 常量；新增组件必须复用这些 token。
- `packages/ui/src/index.ts` 已声明为唯一对外入口；保持这一约束，不引入子路径导入约定。
- `apps/mobile/app/_layout.tsx` 已在根布局使用 `<UIProvider defaultTheme="light">` 包裹 Expo Router Stack；本 Story 不需要改动认证/路由逻辑。
- `apps/mobile/app/(main)/_layout.tsx` 当前仍是 plain Stack，底部 Tab 外壳留给 Story 1.5.4；本 Story 只交付可被其消费的 `BottomTabBar` DS 组件。

### 架构与实现约束

- **包依赖方向**：`apps/mobile -> packages/ui -> packages/shared`；`packages/ui` 不得导入 `apps/*`，不得绑定业务 API、auth store、router 或 Supabase。
- **Tamagui 模式**：优先用 `styled()` + `variants` + token；需要包装逻辑的组件使用 Tamagui `.styleable()` 保持可继续 styled。Tamagui 官方文档强调 variants 建议 `as const`，并说明 `.styleable()` 用于包装组件继续正确转发样式 props。
- **组件命名**：文件 kebab-case，导出组件 PascalCase，Props interface 使用 `<ComponentName>Props` 并从 barrel 导出。
- **TypeScript**：严格模式，禁止 `any`；第三方组件类型不足时用精确类型收窄，不用 `as any` 绕过。
- **样式 token**：颜色、间距、字号、圆角、阴影来自 `tamagui.config.ts` / `token-mapping.md` / `shadows`；不要把高保真 HTML 里的 px 直接复制到组件。
- **图标**：使用 Lucide 图标体系，优先 `@tamagui/lucide-icons` 或现有 mobile 兼容 Lucide 包；不要手写 SVG 图标。
- **可访问性**：所有可交互组件必须有 accessibilityRole / accessibilityLabel；tab/switch/progress/dialog/tooltip/status 等语义按组件 spec 落地。

### 组件特殊要求

- `chart`：`ds-component-implementation-checklist.md` 明确要求使用 Skia，不使用 SVG；`architecture.md` 已选型 `victory-native` 41.20.2+ 与 `@shopify/react-native-skia`。若新增依赖，锁定 exact version 并验证 Expo SDK 54 / RN 0.81.5 兼容。
- `bottom-tab-bar`：组件 spec 是 4 Tab（首页/交易/AI/我的），Epic 1.5.4 当前只落 dashboard/report/my-hub 三 Tab；组件 Props 必须支持任意 tab items，不能把 3 或 4 写死到组件内部。
- `modal-sheet`：spec 允许 Tamagui `Sheet` / `AlertDialog` / `Dialog`；checklist 补充允许 Gorhom BottomSheet。只能选择一种主实现并写清 z-index、backdrop、手势关闭与焦点策略。
- `toast`：必须能由 provider 统一承载；如果需要在 `UIProvider` 内组合 Toast provider，保证现有 mobile 根布局无需额外多处配置。
- `skeleton`：spec 示例使用 `MotiView`，但项目当前未安装 `moti`。若不引入新动画依赖，可用 Tamagui animations/RN Animated 实现同等 pulse；若引入，需说明原因并锁版本。

### Storybook 与测试要求

- Storybook 官方当前提供 React Native Web + Vite 与 on-device React Native 两条路径；本 Story 优先 Web + Vite 作为组件级基线，因为它更适合浏览器隔离预览和后续视觉基线。
- 当前 npm 查询（2026-04-30）显示：`@storybook/react-native@10.3.2`、`@storybook/react-native-web-vite@10.3.6`、`@testing-library/react-native@13.3.3`、`@gorhom/bottom-sheet@5.2.12`、`@shopify/react-native-skia@2.6.2`、`victory-native@41.20.2`。新增依赖必须结合 Expo SDK 54 / React 19 / RN 0.81.5 实测锁定，不使用 `^` 漂移。
- 组件测试不要只测试 barrel export；每个组件至少覆盖 render、variant、interaction、disabled、accessibility。React Native Testing Library 的 `fireEvent` / user interaction API 可用于触发 press/change/focus/blur。
- Storybook stories 命名建议 `<Component>.stories.tsx`，放在 `packages/ui/src/` 或 `packages/ui/src/stories/`，但必须被 Storybook glob 收到。
